Phase 1 of the standalone isohedral tiling library turns the prototype into the package isotile (src layout, hatchling, version 0.1.0.dev0) with the final names (cell, aspect, translation_u, translation_v), find_types, info and describe, check_prototile, safe parameter ranges, fill_region, named constructors for square, hexagon, triangle and quadrilateral tilings, a public frame, a deterministic data build with a --check mode, an exact cover test, 2,835 local tests and a twelve-job CI that is green.

fig.py <output dir> draws the figures from an installed isotile (run with uv run --project <carto-flow> --with <isotile checkout> python fig.py .). They were made at commit cef8334; the later cover change does not alter them.

What changed

  • Package. src/isotile/, hatchling, py.typed, version 0.1.0.dev0, requires-python >=3.10,<4.0, runtime dependencies numpy>=1.26 and scipy>=1.11, extras shapely, plot (empty) and all, dependency groups dev and tactile (installed together by default; the CI matrix leaves tactile out). LICENSE (MIT), NOTICE (Kaplan's BSD 3-Clause text), data/LICENSE-tactile and data/types.npz are in the wheel and the sdist. Ruff with carto-flow's rule set (line length 120), mypy --strict on src/ without exclusions, pre-commit hooks as in carto-flow.
  • Renames, everywhere. translation_u, translation_v, translations (2, 2); TileSet.cell (n, 2) and TileSet.aspect (n,); table columns d_cell_u, d_cell_v, neighbor_aspect; tiles(cell, aspect). tactile's names remain in _build_data.py and the tactile tests only.
  • Types. TilingType with safe_ranges (n_params, 2), n_edge_shapes, edge_shapes (per edge), shape_types (per shape id), has_reflections, info(), describe(); find_types with carto-flow's filters computed from the arrays; info() keys as carto-flow's type_info, affected_vertices exact from vertex_coeffs[:, :, i].
  • Validity. check_prototile(tiling_type, parameters) -> PrototileReport(valid, bad_edges, message) checks zero-length edges, crossing or touching non-adjacent edges, folded neighboring edges and zero area on the straight prototile, without constructing a tiling. The constructor and the parameter setter raise ValueError for an invalid prototile and keep the previous state.
  • Safe ranges. Per type and parameter, the contiguous interval around the default in which the straight prototile stays valid with the other parameters at their defaults. They are computed from the real roots of the orientation determinants of the vertices along the parameter axis (all vertices are affine in a parameter, so validity is constant between roots). Finite ends are rounded inward to a multiple of 1e-6; an end with no root beyond the default is stored as infinity (no limit). 118 of the 256 ends are finite and 138 are infinite (checked valid at plus and minus 10, 100 and 1000 from the default). Polynomial coefficients below 1e-9 count as rounding noise (a spurious root at 2.3e11 had made some type 7 ends finite); the largest real critical value is 0.79 from a default.
  • Tiling. IsohedralTiling(type, parameters=None, *, frame=None); properties vertices, aspects, translations, translation_u, translation_v, edge_transforms, edge_reversed, edge_shape_ids, edge_shapes, area, centroid, frame; prototile(normalized), inscribed_radius, fill, cover, tiles(cell, aspect), fill_region(bounds, *, n_tiles=None, tile_size=None, margin=0.0), with_frame, rotated, scaled, info, describe (both describe the instance: current parameter_values and a value in each parameter entry, with the type's defaults kept under default_parameters and default). Classmethods square() (type 76), hexagon(pointy_top=True) (type 20; pointy_top=False is flat-top), triangle(vertices=None) (type 84, any triangle, default equilateral), quadrilateral(vertices=None) (type 46, any simple quadrilateral, default unit square; self-intersecting ones raise ValueError). cover(bounds) includes a tile iff its straight polygon overlaps the region with an area above 1e-9 times the tile area; touching at a point or along an edge does not count. A strict bounding-box prefilter is followed by an exact vectorized test (Sutherland-Hodgman clipping against the four sides, then the area), valid for any simple polygon, without shapely. A region with non-positive width or height, or non-finite bounds, raises ValueError. TileSet: cell, aspect, transforms, vertices(), centroids, colors(), adjacency(kind) ("edge", "vertex", "vertex-only", scipy csr_array of bool), neighbors(i, kind), polygons() (shapely extra).
  • fill_region. The region is the bounds expanded by margin times width and height on every side. Exactly one of n_tiles (tile size sqrt(region area / n_tiles)) and tile_size (square root of the tile area) is given. The tile area is the area of the straight prototile. The orientation (linear part) of the tiling's frame is kept and scaled; its scale and position are replaced, and the native origin goes to the centre of the region. The result is cover of the region. The count is at least n_tiles, because the tiles cover the region.
  • Data build. python -m isotile._build_data writes types.npz deterministically (sorted keys, fixed dtypes, uncompressed, fixed time stamps); --check rebuilds and fails on any difference in dtype, shape or value. The adjacency tables are identical to the prototype's. The file is 390 KB (173 KB compressed).
  • CI (.github/workflows/main.yml): lint; typecheck; tests with coverage on Python 3.10 to 3.13 (Linux) and 3.12 (macOS, Windows) without tactile; tactile equivalence job; _build_data --check; lowest direct versions; wheel smoke test (build wheel and sdist, wheel from the sdist, data files compared with the source tree, clean venv, tiles for all 81 types). No publish workflow.

Deviations from the design page and the brief

  • tactile is in its own dependency group included by default, not inside dev.
  • CI uses uv 0.8.17 (carto-flow 0.6.14); no Codecov upload, a coverage artifact instead. Coverage in the CI matrix is about 85 percent because fill is only fully exercised by the tactile tests.
  • safe_ranges from exact roots instead of a scan (a 0.01 scan missed isolated degenerate values, for example IH41 parameter 0 at -0.02564); unbounded intervals are stored as infinity (no cap). Some limits are isolated degenerate values beyond which the prototile is valid again; the interval is the contiguous one around the default. check_prototile reports some valid but extremely elongated prototiles as degenerate at about 1e6 from the default, because its tolerances are relative to the squared longest edge.
  • Coverage of fill_region is checked by summed parts and point sampling, not by one union overlay (GEOS gave a 0.0015 area deficit on macOS and Windows for the union; cause not confirmed).
  • The data check compares arrays; bytes are identical only for the same numpy version.
  • fill is tactile-equivalent and does not guarantee coverage of the rectangle; cover and fill_region do.
  • cover is the exact positive-overlap test described above (decided after review: the first exact version counted touching tiles, which added a ring of 404 tiles for the square tiling in the unit square). On the aligned region (0, 0, 1, 1) the counts are: type 76 1,024 and 10,000 tiles at about 1,000 and 10,000; type 20 1,067 and 10,301; type 7 1,068 and 10,300; type 46 1,024 and 10,000 (the bounding-box rule counted 10,151: 151 tiles that touch the region edge up to rounding noise of about 1e-17); type 84 1,118 and 10,108.
  • inscribed_radius is exact for convex prototiles (linear program); non-convex ones use branch and bound to 1e-7 of the bounding-box size, capped at 200,000 squares. carto-flow's measure (centroid to boundary) is a different quantity and was not compared.
  • TilingType.edge_shapes is per edge; the stored per-shape-id names are shape_types.
  • The data-layer commit does not pass its own tests until the core-API commit that follows.
